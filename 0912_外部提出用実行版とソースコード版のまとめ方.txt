DX22 外部提出用「実行版」と「ソースコード版」のまとめ方

============================================================
■最初に結論
============================================================

提出物は、次の2つのZIPに分けるのが分かりやすく安全です。

1. DX22_作品名_実行版_20260912.zip
   Visual Studioを入れていない人が、展開してExeを起動するためのもの。

2. DX22_作品名_ソースコード_20260912.zip
   Visual Studio 2022でソリューションを開き、コードを閲覧・ビルドするためのもの。

実行版とソースコード版を一つのZIPに混ぜると、起動する場所や見るべきファイルが
分かりにくくなり、容量も大きくなるため、分けて提出することを推奨します。


============================================================
■重要：このプロジェクトで提出前に直す必要がある点
============================================================

現在のAssimp設定は、DebugとReleaseの両方で次のデバッグ用ライブラリを指定しています。

  DX22_01_plane\AssimpPerse.cpp
  #pragma comment(lib, "assimp-vc143-mtd.lib")

現在作成済みのRelease版Exeも「assimp-vc143-mtd.dll」を要求しています。
このDLLはさらに、MSVCP140D.dll、VCRUNTIME140D.dll、ucrtbased.dllなど、
通常の利用者PCには入っていないVisual C++デバッグランタイムを要求します。

したがって、現在のRelease版Exeをそのまま外部提出用にしないでください。
提出前に、AssimpのRelease用ライブラリとDLLを用意し、例えば次のように切り替えます。

  #ifdef _DEBUG
  #pragma comment(lib, "assimp-vc143-mtd.lib")
  #else
  #pragma comment(lib, "assimp-vc143-mt.lib")
  #endif

Release用の実際のファイル名が異なる場合は、手元のAssimpビルドに合わせます。
現在の C:\assimp\5.2.5\lib にはデバッグ用しか見つからないため、Release版Assimpを
別途ビルドまたは用意してから、Release x64をビルドし直す必要があります。

修正後は、Visual Studio付属のdumpbinなどでRelease版Exeの依存DLLを確認し、
末尾が「D」のデバッグランタイムや「mtd」のデバッグDLLが残っていないことを確認します。


============================================================
■1. 実行版を作る手順
============================================================

【1】提出する版を確定する

・作業途中のファイルを混ぜないよう、提出時点のバックアップを取る。
・可能ならGitで提出用コミットまたはタグを作る。
・ステージ、球、デバッグ機能など、提出したい変更がすべて入っているか確認する。
・個人用のセーブ、デバッグプリセット、ログは提出物へ入れない。

【2】Visual StudioでRelease x64をビルドする

1. DX22_01_plane.sln をVisual Studio 2022で開く。
2. 画面上部の構成を「Release」、プラットフォームを「x64」にする。
3. 「ビルド」→「ソリューションのリビルド」を実行する。
4. エラー0件であることを確認する。
5. 出力先の x64\Release\DX22_01_plane.exe を確認する。

外部提出用は、原則としてDebugではなくRelease x64を使用します。
Debug版は容量が大きく、開発用DLLやデバッグランタイムへ依存しやすいためです。

【3】実行版フォルダーを新しく作る

例：

  DX22_作品名_実行版\
    はじめに.txt
    DX22_01_plane.exe
    assimp-vc143-mt.dll
    litTextureVS.cso
    litTexturePS.cso
    unlitTextureVS.cso
    unlitTexturePS.cso
    assets\
      data\
      model\
      texture\
    LICENSES\

コピー元は次のとおりです。

・Exeと4つの.cso：x64\Release\ からコピー
・AssimpのRelease用DLL：使用したAssimpのbinフォルダーからコピー
・assetsフォルダー：DX22_01_plane\assets をフォルダーごとコピー
・第三者ライブラリや素材のライセンス／Readme：LICENSESへ整理してコピー

このゲームは「assets/data/...」のような相対パスでデータを読み込みます。
そのためExeとassetsを上記の位置関係にし、Exeを実行版フォルダーの直下へ置きます。
Exeだけを単独で渡すと、画像、モデル、ステージデータなどを読み込めません。

【4】実行版へ入れないもの

・.pdb、.ilk、.lib、.exp、.objなどの中間・デバッグファイル
・x64\Debug、各種テスト用Exe
・.vs、.git、ビルド中間フォルダー
・tools、テストコード、MCP用ツール（実行版では不要）
・saves、logs、および自分のプレイ履歴
・古いExeや、使用していないDLL

.pdbはクラッシュ調査を依頼する場合のみ、一般公開物とは別に保管します。

【5】「はじめに.txt」へ書く内容

最低限、次を記載します。

・作品名、制作者名、バージョン、作成日
・対応OS（例：Windows 10/11 64bit）
・起動方法：「ZIPをすべて展開後、DX22_01_plane.exeを実行」
・基本操作、ゲームパッド／キーボードの対応
・終了方法、フルスクリーン切替などの補助操作
・初回起動時にWindowsの警告が出る可能性
・既知の不具合
・使用ライブラリと素材のクレジット
・連絡先を載せる場合は提出用のものだけを使用

「ZIPの中から直接Exeを起動せず、必ず全ファイルを展開してください」と明記します。
本作品は実行場所にsavesとlogsを作るため、書き込み可能な場所へ展開してもらいます。

【6】Visual C++ランタイムを確認する

Release版ExeとAssimp DLLの依存関係を確認します。
MSVCP140.dllやVCRUNTIME140.dllを要求する場合は、次のいずれかにします。

・Microsoft Visual C++ 2015-2022 Redistributable x64が必要だと明記する。
・配布条件を確認した正規の再頒布パッケージを同梱する。
・すべてを静的ランタイムで統一して再ビルドする。

「自分のPCで動いた」だけでは、ランタイム確認になりません。

【7】素材の利用・再配布条件を必ず確認する

assets\model\JACK式ピピ美_v1.0\readme.txt には、二次配布禁止や、
作品公開時のクレジット表記・コンテンツツリー登録に関する条件があります。

現在の実行版はPMXや画像をassets内へそのまま入れる構成なので、第三者へ渡す行為が
許可範囲に含まれるか、利用規約の文字コードを正しく表示して必ず確認してください。
許可が明確でなければ、配布可能な自作・許諾済み素材へ差し替えるか、権利者へ確認します。
Readmeを消して配布することは避けてください。

学校・企業への限定提出であっても、自動的に再配布可能になるとは限りません。
判断に迷う場合は、学校の担当者や権利者へ確認してください。

【8】提出用とは別のPC環境で動作確認する

最も重要な確認です。可能ならVisual Studioを入れていないWindows 10/11のPC、
またはクリーンなWindows環境で、完成したZIPだけを使って確認します。

確認項目：

□ ZIPを新しいフォルダーへ展開できる。
□ Exeをダブルクリックしてタイトル画面まで起動できる。
□ テクスチャ、3Dモデル、文字が欠けていない。
□ 新規ゲームを開始し、通常戦とボス戦を遊べる。
□ ブレイクボールや各球種が正常に動作する。
□ シーン移動、ポーズ、設定、終了ができる。
□ ゲームパッドを抜いた状態でも異常終了しない。
□ savesとlogsを作成できる。
□ Exeの隣からassetsやDLLを一時的に外すと失敗することを確認し、必要物の漏れがない。
□ デバッグ用DLL不足、DirectX関連DLL不足のエラーが出ない。
□ 個人名、APIキー、トークン、個人用パス、不要なログが入っていない。

確認後、実際に動作確認したフォルダーをZIPにします。
ZIP化後も、一度別の場所へ展開して最終起動確認を行います。


============================================================
■2. Visual Studioで開けるソースコード版を作る手順
============================================================

【1】ソースコード版の基本構成

例：

  DX22_作品名_ソースコード\
    ソースコードを開く方へ.txt
    DX22_01_plane.sln
    DX22_01_plane\
      DX22_01_plane.vcxproj
      DX22_01_plane.vcxproj.filters
      *.cpp
      *.h
      シェーダーのソースファイル
      imgui\
      nlohmann\
      assets\（利用条件上、同梱可能なものだけ）
      tools\（テストや検証方法も見せたい場合）
    各実装意図のテキスト資料

Visual Studioで使うため、次は必ず残します。

・DX22_01_plane.sln
・DX22_01_plane.vcxproj
・DX22_01_plane.vcxproj.filters
・プロジェクトが参照しているすべての.cppと.h
・imgui、nlohmannなど、リポジトリ内で直接参照しているコード
・シェーダーのソースと、必要ならビルド済み.cso
・ビルドに必要なJSON、モデル、テクスチャ

【2】ソースコード版へ通常入れないもの

・.vsフォルダー
・x64\Debug、x64\Release
・Debug、Release、中間生成物
・*.obj、*.pdb、*.ilk、*.tlog、*.lastbuildstate
・saves、logs、runtime_testsの生成物
・.gitフォルダー（履歴提出を求められた場合を除く）
・APIキー、トークン、個人情報、個人用設定

ただし「ソースと一緒に、すぐ試せるExeも必要」と提出要項にある場合は、
実行版ZIPを別に付け、ソースフォルダー内へビルド生成物を混ぜない方が明確です。

【3】ビルド環境を記載する

「ソースコードを開く方へ.txt」に、少なくとも次を記載します。

・Visual Studio 2022
・「C++によるデスクトップ開発」ワークロード
・Platform Toolset v143
・Windows 10/11 SDK
・C++20
・ビルド構成：Release x64
・DirectXTKの使用バージョン、入手元、ライセンス
・Assimpの使用バージョン、入手元、ライセンス
・ソリューションを開いてからビルドするまでの手順

【4】現在の外部ライブラリパスに関する注意

現在のプロジェクトファイルには次の絶対パスが設定されています。

  C:\directxtk\include
  C:\directxtk\lib\x64\Debug または Release
  C:\assimp\5.2.5\include
  C:\assimp\5.2.5\lib

そのため、受け取った人のPCに同じ位置でライブラリを配置しない限り、
ソリューションを開いただけではビルドできません。

提出方法は次の2案があります。

A. 現状を維持する方法
   上記と同じフォルダーへDirectXTKとAssimpを用意する手順を、説明書へ明記する。
   作業量は少ないが、受け取る側の準備が多くなります。

B. 推奨方法
   externalまたはthird_partyフォルダーへ必要な依存物をまとめ、
   Visual Studioのインクルード・ライブラリパスを$(SolutionDir)から始まる相対パスへ変更する。
   依存物を同梱する場合は、それぞれの再配布ライセンスと著作権表示も同梱します。

就職作品として見てもらう場合は、Bの方が「受け取ってすぐ開ける」ため親切です。
ただし、ライブラリ本体をリポジトリへ含められるかは各ライセンスを確認してください。

【5】ソース一覧を付ける

「ソースコード一覧.txt」を別途作り、機能ごとの主要ファイルを書いておくと、
見る人が短時間で作品の工夫を確認できます。

例：

・ゲーム進行：Game.cpp / RunController.cpp / BattleScene.cpp
・ボール物理：BallPhysicsWorld.cpp / BallCollisionComponent.cpp
・ショット予測：BallShotPrediction.cpp
・プレイヤー球：PlayerBall.cpp / PlayerBallDataLoader.cpp
・敵・ボス：EnemyBall.cpp / GameBossAI.cpp / BossCombatRules.h
・ブレイクボール：BreakBall.cpp
・ステージ：StageDataLoader.cpp / StageLayoutEditor.cpp / GameStageEditor.cpp
・セーブ：GameSaveManager.cpp / GameSaveSystem.cpp / ProgressionProfile.cpp
・描画：Renderer.cpp / BallRenderComponent.cpp / TableFrameRenderComponent.cpp
・デバッグ・検証：GameDebugMode.cpp / GameMcpBridge.cpp / tools\

全ファイルを一行ずつ並べるより、「どこを見れば何が分かるか」を示す方が有効です。

【6】ソースコード版を別の場所で確認する

1. 完成したソースコード版ZIPを、元の開発フォルダーとは別の場所へ展開する。
2. DX22_01_plane.slnをVisual Studio 2022で開く。
3. Release x64をリビルドする。
4. 元の C:\HAL\... にあるファイルを誤って参照していないか確認する。
5. 作成されたExeを実行し、最低1戦プレイする。

別の場所でビルドできなければ、提出先でも同じ問題が起きる可能性が高いです。


============================================================
■3. 提出直前の最終チェック
============================================================

□ 実行版ZIPとソースコード版ZIPを分けた。
□ Release x64を最新ソースからリビルドした。
□ Release版がデバッグ用Assimp DLL／デバッグランタイムへ依存していない。
□ Exe、Release用DLL、4つの.cso、assetsが正しい位置にある。
□ 実行版ZIPだけを使い、別PCまたはクリーン環境で起動確認した。
□ ソースコード版を別フォルダーへ展開し、Visual Studioで開けた。
□ 外部ライブラリの導入方法とバージョンを書いた。
□ 第三者ライブラリ・画像・モデルのライセンスとクレジットを確認した。
□ JACK式ピピ美モデルの配布可否と公開条件を確認した。
□ 個人用のsaves、logs、APIキー、トークンを除外した。
□ 提出先の容量制限・ファイル形式・命名規則を確認した。
□ ウイルス対策ソフトでZIPを確認した。
□ ZIPを再展開し、最終的にもう一度Exeを起動した。


============================================================
■推奨する提出物
============================================================

・DX22_作品名_実行版_20260912.zip
・DX22_作品名_ソースコード_20260912.zip
・作品紹介.pdf または 作品紹介.txt
・操作説明.txt
・使用素材・ライセンス一覧.txt

動画提出が許可されている場合は、起動から通常戦、球種固有効果、ボス戦までを
短く見せるプレイ動画も用意すると、環境問題でExeを起動できない場合の補助になります。


============================================================
■この手順書作成時点の確認結果
============================================================

・ソリューション：DX22_01_plane.sln
・Visual Studio構成：Debug/Release、Win32/x64
・推奨提出構成：Release x64
・ゲームデータ参照：assetsを相対パスで参照
・シェーダー：4つの.csoが実行時に必要
・外部DLL：Assimp DLLが必要
・アプリ本体のReleaseランタイム設定：MultiThreaded（/MT）
・現在のAssimpリンク：デバッグ用mtd固定のため、外部提出前にRelease用へ修正必須
・セーブ／設定：savesフォルダーへ作成
・ログ：logsフォルダーへ作成
・第三者モデル：個別Readmeの再配布・公開条件を提出前に要確認
