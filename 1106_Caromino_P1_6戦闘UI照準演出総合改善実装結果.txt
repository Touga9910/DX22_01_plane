# Caromino P1.6 戦闘UI・照準・演出の総合改善 実装結果

## 1. 結論

P1.6の9項目を、物理・ダメージ・敵AI・SEを変更せず実装した。既存の`GamePresentation`、共有ショット予測器、戦闘イベント経路、P1.5のHPリングを再利用し、新規Manager・Singletonは追加していない。

Release x64とDebug x64はともにビルド成功、関連8テストはすべてPASSした。実ショットのRelease計測は平均59.97 FPS、平均フレーム16.674 msで、過去の通常設定約60 FPSを維持した。

## 3. 実装の要点

### HPリングと描画順

`EnemyBall::GetVisualRadius()`は`BallRenderComponent::GetModelBaseRadius()`と`BallComponent::GetScale()`から見た目の半径だけを計算する。この値はUI投影にのみ使用し、`BallComponent::GetRadius()`、衝突、CCD/TOIには渡さない。よって、明示的な物理半径とモデル半径が異なる敵でも、リングは球モデルに合う。

HPリングとDense接続線はBackground draw listとした。行動・状態ブロックはカードより先に作成し、後から作成されるカードwindowに隠れる。敵のワールド情報がカード操作を妨げないことを優先した。

### 照準予測

1. 現在の実ショット速度で`GameShotPrediction::Predict`を実行する。
2. `PreviewPointCount(0)`で最初の接触までに制限する。
3. 現在パワーで接触へ届かない場合のみ、同じ方向・最大パワーで共有予測器を1回追加呼び出す。
4. 現在パワーの移動距離までを実線、その先を破線とする。
5. 現在パワーが到達しない対象には、ゴースト球、対象球方向線、連鎖範囲を出さない。未確定命中を表示しない。

予測器は読み取り専用で、実ショットの速度、摩擦、衝突解決は変更していない。

### MULTI BREAKと軌跡

`BeginDefeatReaction`は既存の重複撃破抑制後に一度だけ計数する。そのため、同じ撃破の複数経路からポップが多重発火しない。ショット停止直後に即消去していた処理を外し、次ショットまたはタイマー終了まで読める。

削除したのは`GamePresentation::DrawFeedback`内のスクリーン座標ライン3層だけである。`PlayerBall::Draw`の小球メッシュ残像データは残している。

## 4. Presentationとルールの責務分担

| 層 | 責務 |
|---|---|
| 物理／ルール | 実ショット、摩擦、衝突、HP、ダメージ、敵行動決定、スタックを従来どおり管理 |
| 読み取りビュー | `EnemyBall::GetVisualRadius`、`PlayerBall::GetShotPowerRatio`が描画に必要な値のみを公開 |
| Presentation | HPリング、行動バッジ、パワー円弧、Dense配置、MULTI BREAKタイムライン、カードとの描画順を管理 |
| 共有予測 | 実物理と同じCCD/TOI予測結果を返す。Presentationはパスを切り詰め、実線／破線の意味付けだけ行う |

新しい描画型はGameEventに追加していない。撃破数は既存の戦闘フィードバック／`ShotResolvedEvent`経路、予想ダメージは確定済み`EnemyAttackComponent`と既存の被ダメージ計算を読み取る。

## 8. プレイヤー体験の変化

### 変更前

- 敵行動ブロックが横長で、Dense配置の対応関係が崩れやすかった。
- モデルと物理半径の差でHPリングが大きすぎる／小さすぎる可能性があった。
- 低パワーの照準線から、「方向は合っているがパワー不足」を判別しにくかった。
- 反射球だけ表示情報が多く、不確実な反射後の線を確定軌道のように読む可能性があった。
- 黄色の線軌跡と小球残像が二重表現になっていた。

### 変更後

- 「どの敵が何点攻撃するか」を敵直下の剣アイコンで素早く読める。
- 狙う敵とHPの対応関係がモデルサイズに対して安定する。
- 実線は「現在パワーで実際に届く」、破線は「方向はこちらだが現在は届かない」を意味する。
- パワー円弧で、視線を球から外さずに引き量を調整できる。
- 全軸の照準情報量が第1接触までに統一され、照準決定の迷いを減らす。
- 連続撃破のたびにMULTI BREAKが跳ね、ショットの成果が段階的に強調される。

主に改善するピラーは「照準」で、副次的に「選択」と「連鎖結果の理解」を改善する。

## 9. 残存リスクと未完了検証

1. 低パワー時は共有予測器を最大パワーで追加呼び出すため、マウス移動中の予測コストが増える。通常ショットのRelease性能は良好だが、Dense10で照準を連続更新する専用計測は追加候補である。
2. 破線の切り替えは予測パスのセグメント境界単位であり、到達距離とセグメント境界の間に最大1ステップ分の見た目の差がある。
3. HPリングはカード優先のためBackgroundに固定した。P1.5のForeground指定値は設定互換のため保持するが、現行表示ではカード優先制約が上位となる。
4. GameMCPコネクタは2回ともトンネルサービスからHTTP 429を返した。ゲーム本体の`runtime/game_mcp/game_state.json`は更新され、計測値は読み取れたが、固定seedのUI ON/OFF完全比較とGameMCPによるDense10操作は未完了。
5. Dense6/8/10の基本配置と追従は追加項目09実装時に実機確認済み。今回の最終ビルドでの比較キャプチャ保存は、上記GameMCP接続回復後の追加作業とする。

## 10. 推奨する追加検証順序

1. GameMCPトンネル回復後、固定seedと固定ショット列でUI ON/OFFのHP、敵位置、衝突数、ダメージ、スタックの完全一致を比較する。
2. Dense6/8/10の同一配置で、カード通常／ホバー拡張、低／中／高パワー照準、故意の到達不足を撮影する。
3. 反射球を選択し、最初の壁接触以降のプレイヤー軌道が出ないことを撮影する。
4. 2～5体を1ショットで撃破し、撃破ごのポップ再開、最終表示の0.8秒保持と1.0秒フェードを60 fps撮影で確認する。
5. Dense10の照準中にフレーム計測を行い、`shot_prediction`の平均／p95／最大呼び出し時間を追記する。
