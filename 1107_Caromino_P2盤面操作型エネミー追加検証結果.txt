# Caromino P2 盤面操作型エネミー追加・検証結果

## 実装前の成功条件

- プレイヤーに見える変化：敵の配置、壁衝突、射程内外による攻撃力・脆化・防護の変化をバッジと短い通知で読み取れること。
- 改善の柱：「倒す」だけでなく「引き離す」「壁へ当てる」「防護範囲を崩す」を実ダメージに反映する。
- 変更対象：既存の敵データ、敵球ルール、既存壁衝突イベント、ショット終了時処理、GameEvent/Presentation、BalanceLogger/分析器、固定検証ステージ。
- 主なリスク：攻撃予告と実ダメージの差、防御の二重計算、同一ショットでの多重発動、プレゼンテーションがゲーム結果を変えること。
- 成功確認：ルール境界値、JSON読込、攻撃予算/Charge、既存敵・ボス・進行・マップの自動テストと、固定配置での人手プレイテストを分けて判定する。

## 1. 既存システムの調査結果

- `EnemyData` と `StageDataLoader` は敵のステータス、物理値、ギミック、ステージJSONを管理している。既存の normal/strong/tank を変更せず、`gimmick.boardAbility` を任意フィールドとして拡張した。
- `EnemyActionPlanner` は行動種別と攻撃予算を決める責務のままとし、今回の能力判定を追加していない。
- `BattleController` はショット前に行動を計画し、停止後に Charge 妨害と敵行動を解決する。位置依存状態の再評価点としてこの境界を利用できる。
- `BallCollisionComponent` は固定ステップ/CCD後の実際の壁反射と衝突前速度を既に持つ。新しい物理判定は追加せず、接受済みの壁衝突事実を再利用した。
- `GameEvent` と `GamePresentation` はルールと表示を分離できる。Presentation側は範囲や衝突を再判定せず、ゲーム側が確定した状態変化イベントのみを表示する。
- `BalanceLogger` とバランス版基盤は既に存在した。新しい管理基盤は作らず、任意の `shot_events` と既存のバージョン登録を拡張した。

## 2. 3種類の新敵の仕様

### 群体強化球 `enemy_swarm_amplifier`

- 自分以外の生存中かつ未ポケットの味方をXZ平面上で数える。
- 0～1体は攻撃1、2～3体は攻撃2、4体以上は攻撃3。上限は3。
- ステージ開始時とショット終了時に再評価し、引き離し・撃破・再接近を反映する。
- 頭上の「群」バッジ、周辺数/段階/現在攻撃力のツールチップ、`SWARM UP/DOWN` 通知、デバッグ範囲円を追加した。

### 衝撃脆化球 `enemy_impact_brittle`

- 通常攻撃3、脆化中攻撃1。接触だけでは発動せず、接受された壁反射の衝突前速度が閾値以上の場合のみ発動する。
- 次の実行済み敵攻撃1回に適用し、Waitや中断では消費しない。同一ショットで再発動しても1回分に更新し、累積しない。
- 通常時の「衝」と脆化中の「脆」バッジ、`WALL BREAK/BRITTLE END` 通知を追加し、発動時は既存 `CollisionVfxSystem` を再利用する。

### 防護共鳴球 `enemy_protection_resonator`

- 範囲内の生存中かつ未ポケットの味方の最終被ダメージを1軽減する。自分は対象外。
- 複数源があっても最大軽減量のみを使い、重複しない。1ダメージは0になり得る。0ダメージで撃破判定は発生しない。
- ダメージ確定時の現在位置で都度判定するため、ショット中の範囲への出入り、源の撃破、ポケットを即時反映する。
- 源の「響」、保護対象の「護」バッジ、`PROTECTED/PROTECTION LOST` 通知、ホバー/デバッグ用範囲円を追加した。

## 4. 敵行動・位置依存判定の設計

1. ステージ開始時に能力状態を初期化し、既存の `EnemyActionPlanner` が行動種別と予算を確定する。
2. プレイヤーは予告と現在の能力バッジを見てショットする。
3. 固定ステップ/CCDの衝突解決中、脆化は接受済みの壁反射時に判定し、防護は各ダメージ確定時の位置で判定する。
4. 物理停止後、先に既存の Charge 妨害を解決し、その後で群体段階と防護表示状態を1回更新する。
5. 当初の行動種別と予算は変更せず、実行直前の最終攻撃力だけを使って解決する。脆化は実際に攻撃した後のみ1回分を消費する。

この順序により、ショット前の「強い行動予告」自体は残しながら、盤面操作の成果を実ダメージに反映する。状態変化は理由付きイベントとしてUIとログへ配信する。

### Release実機スモーク結果

- 固定シード `20261107` の複合6体配置で新敵3種の生成を確認した。群体強化球は初期攻撃2から散開後1へ低下し、`nearby_living_allies=1`、`swarm_attack_reduction=1`に相当するイベントを記録した。
- 同じショットで防護による1ダメージ軽減を3回、配置崩れによる `protection_removed` を確認した。
- 固定シード `20261109` の壁際隔離配置で、衝突速度 `7.699` が閾値6を超えて脆化を発動した。脆化球の攻撃は4→1（ステージ難度補正込み）、同ターンの合計被ダメージは3、次ターンは通常に戻って合計6となり、1行動だけ適用されることを確認した。
- 実機ログで `qualifying_wall_impact`、`enemy_brittle_player_damage_reduced(prevented_damage=3)`、`brittle_action_consumed` を確認した。敵行動は `EndShot` 後のため、分析器は二重集計を避けつつルート `events` を1回読む実装に修正した。

人手での4軸別プレイ、同一シードのPresentation ON/OFF完全一致、操作の面白さは未評価。自動テスト成功を「面白くなった」根拠にはしない。

## 7. テレメトリ追加項目

- `enemy_swarm_sample`：周辺生存味方数、段階、実攻撃力。
- `enemy_board_ability_state_changed`：能力ID、変化理由、前後段階、前後攻撃力、衝突速度。
- `enemy_brittle_player_damage_reduced`：通常時/脆化時ダメージと防止量。
- `enemy_protection_damage_reduced`：防護前後ダメージと防止量。
- `enemy_defeated`：敵IDと盤面能力ID。
- 分析器は発動/解除回数、攻撃減少量、軽減ダメージ、出現/撃破数、対象ステージのショット数を `board_control_enemies` に集計する。
- 位置変化はショット中に、脆化攻撃/消費は `EndShot` 後に起きるため、分析器はルート `events` から一度だけ集計する。過去ログに追加イベントがない場合は零を捏造せず `null` とし、既存ログを書き換えない。

## 9. Debug/Releaseビルド結果

- Release x64：インストール済みPDBツールの不整合だけを回避する一時的な `/Z7` 設定で、全ソースのコンパイル/リンク成功。0警告、0エラー。設定変更は最終プロジェクトに残していない。

## 11. 残された課題と今後の調整候補

1. Visual StudioのPDBコンポーネントを修復し、標準 Debug x64 ビルドを再実行する。
2. Python環境を用意し、`test_analyze_balance_logs.py`、`test_balance_configuration.py`、`test_balance_version.py` を実行する。
3. 固定ステージでPresentation ON/OFFを同一シード比較し、最終HP、撃破数、行動数、ショット数が一致することをログで確認する。
4. 重量での引き離し、貫通での防護範囲打開、反射での壁脆化、Anchorでの配置固定を人手プレイし、別の攻略として選ばれるか記録する。

6. 初期値の調整候補は、群体半径12.5、脆化閾値6、共鳴半径16。脆化閾値は実機確認で最大ショット速度8に対し当初値18が到達不可能と判明したため6へ修正した。発動率だけでなく、そのためにプレイヤーが狙いを変えた割合を人手フィードバックと併せて判断する。
