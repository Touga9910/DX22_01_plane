0903 ルートマップ式進行の実装

■ 目的
各ステージのたびに3択を再抽選する方式から、先の施設・戦闘と接続先を見て経路を選ぶ方式へ変更。

■ プレイヤーから見た変更
・ラン開始時に通常15エリア分のマップを生成。3レーンに分岐・合流があり、直前のノードに接続する行き先だけを選べる。
・画面の下から上へ進む。ノードをクリック、または右側の行き先ボタンをクリックして出発。
・スクロールで先を確認し、「全体表示」で最終ボスまで見渡す。「現在地へ」で次の選択地点へ戻る。
・通過済みは金色、選択できるノードは太い枠、到達できなくなった道は暗く表示。各施設に説明を付けた。
・通常15エリア → 必ずボス前休憩 → 最終ボス、という既存の終着点を維持。ボス前休憩は自動入場。

■ 配置の初期ルール（生成バージョン1）
・最初の2エリアは通常戦闘。選んだレーンによって、その先の接続が変わる。
・4・8・12エリアの中央に休憩所を置き、直前のどのレーンからも選べる接続を用意。回復へ寄るか別の道へ進むかはプレイヤーが選ぶ。
・3・7・11・14エリアにショップ、5・10・15エリアに中ボスの候補を配置。
・その他の初期抽選は通常95、中ボス19、ショップ18、休憩18の比率を基礎とする。各行には通常戦闘を最低1つ置く。
・施設や中ボスは配置候補であり、すべての経路から必ず選べる保証ではない（上記の定期休憩は保証）。
・配置保証や序盤の制約があるため、最終的なマップ全体の出現率は旧方式の12%と同じではない。旧ランとの勝率を単純比較しない。
・戦闘内の敵配置は従来どおり、選んだノードへ入るときにステージ選択処理で決まる。

■ セーブとログ
・マップ生成バージョン、シード、開始地点、通ったノード、現在攻略中のノードを保存。ロードやマップ画面への再入場で再抽選しない。
・経路の飛び越し、二重選択、壊れた保存経路を拒否する。
・旧形式セーブは再開地点から先のマップを作り、ショップ・休憩所・戦闘内からの再開も維持。過去の選択は不明なので架空の通過履歴は作らない。
・通常ランのセーブは既存ルールに従う。バランス検証・自動プレイ時の保存制限は既存どおり。
・run開始ログにマップ全体、route_choiceにmap_node_idとmap_path、エリア完了に通過経路を追加。
・明示的な耐久検証では15エリアごとに次の区間のマップを生成して継続する。

■ MCP
・get_game_stateのrun_mapで全ノードとnext_node_ids、visited、active、reachable、selectableを公開。
・route_optionsは現在接続している選択肢のみ。node_idと接続先も付加。
・マップのroute_indexを明示した場合、その道を選択する。低HPや購入不可ショップを理由に別の経路へ自動変更しない。
・route_index省略時は従来の報酬・回復優先の自動選択を利用。こちらは直近の選択で、先読み経路の最適化ではない。
・MCP AI向けの説明に、先の回復・購入・中ボスまでの接続を見て選択する案内を追加。
・C++自動プレイは現在接続している行き先を選ぶ。長期経路の評価は今回追加していない。

■ 検証
・Debug / x64 ビルド成功。
・既存のPythonテスト90件、MCP側93件（新規経路ポリシー3件を含む）に合格。
・C++実動テストで200シードの到達性、接続、回復地点へのアクセス、ショップ・中ボスの予定配置の保持、途中・終盤セーブ往復、旧保存への入口、壊れた経路の拒否を確認。
・専用のテスト用保存先で実画面とマウス選択を確認。中央ノードを選び、ゲーム再起動後に同じ戦闘・マップへ復元できた。
・ボス前休憩を復元 → 回復 → 最終ボスのみ選択可能 → ボス戦開始を確認。
・旧形式のショップ途中セーブを移行 → エリア15完了 → ボス前休憩へ自動入場することを確認。
・今回の終盤テストは保存データのテスト用チェックポイントを使用。新マップで1ランを通してクリアした検証や勝率評価ではない。
