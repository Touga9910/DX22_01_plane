# 0902やることリスト：①〜③の実装

④の新規プレイヤーボールは追加せず、既存の5種類を使用する。

## ① 最大HPの分離

- プレイヤー最大HPは `assets/data/player_status.json` 直下の `maxHp`（50）で設定する。`currentHp`、`restHealRatio` も従来どおり同じファイル直下にある。
- 共通の `BallStatus` と各プレイヤーボール定義から最大HPを削除。ランのHPは `PlayerRunStatus` が管理し、戦闘中のコンポーネントへ反映する。
- 敵は `EnemyData.maxHp` に分離。既存の調整ツールとの互換性のため、敵JSONの `status.maxHp` は読み込み窓口として維持する。
- ボール交換・強化でランの最大HPは変わらない。

## ② 既存ボールの強化軸

値は「未強化 → +1 → +2」。記載のない性能は前段階を引き継ぐ。強化費用・強化回数の上限・休憩所の利用回数は従来どおり。

| ボール | 強化内容 |
|---|---|
| Standard | 攻撃 2 → 3 → 5、防御 0 → 1 → 2 |
| Heavy | 質量 4 → 5 → 6、敵へのノックバック伝達倍率 1.00 → 1.15 → 1.30 |
| Pierce | 1ショットの貫通回数 1 → 2 → 3、貫通後の速度維持率 75% → 85% → 95% |
| Bounce | 壁反射後の速度維持率 90% → 95% → 100%、摩擦 0.010 → 0.008 → 0.006 |
| Anchor | 減速倍率 1.0 → 1.4 → 1.8、停止判定の速度二乗 0.03 → 0.06 → 0.10、+1以降は停止中のノックバック無効 |

補足：

- Standardはリストの選択肢のうち「単純なスタッツ強化」を採用。
- Heavyは敵へ伝える力を強化し、攻撃・防御は増やさない。壁への衝突には伝達倍率を適用しない。
- Pierceは貫通回数を使い切ると通常衝突する。複数の敵に重なっても接触ごとの判定を保持し、同じ重なり中の再ヒットを防ぐ。予測線も強化後の回数・維持率を参照する。
- 貫通用レリックは強化後の回数にさらに+1、速度維持率100%。
- Bounceは未強化時の反発係数を従来の1.0から0.9に変更し、2段階で1.0まで伸ばす。強化しても反射で加速はしない。
- Anchorは従来の「敵へ衝突の力を伝えた後、その場で停止」を維持。+1以降は停止済みの球に敵が当たっても、速度・位置の両方を押し戻されない。
- 報酬・休憩所に強化前後の性能を表示。選択・購入画面にも個体の性能を表示する。
- 保存時は物理性能と強化表をまとめて保存。旧セーブは個体ID・強化段階・ランHPを保持し、既知のボールを新しい強化軸へ移行する。

## ③ 中ボス2種類

資料の案から方向軽減型とポケット特効型を採用。分裂型・環境変化型は候補のまま保留する。

### ガード球（水色）

- `enemy_midboss_guard`、HP12、攻撃1、質量2.2。
- テーブル手前（-Z）を中心とする120度の範囲から受ける衝突ダメージを50%軽減。端数切り上げ、最低1ダメージ。
- 軽減方向は固定。側面・奥側からの攻撃は軽減しない。プレイヤー球だけでなく敵同士の衝突にも適用。
- `midboss_001` に通常敵2体と出現する。

### ポケット球（緑）

- `enemy_midboss_pocket`、HP18、攻撃1、質量1.6。
- ポケットに落とすと最大HPの45%ダメージ（切り上げ、基準HPなら9）。防御・方向軽減を無視する。
- ダメージ後に既存の中ボス用ポケット撃破判定（残HP20%以下）を適用。生存時は既存の待機列へ入り、後で復帰する。
- `midboss_002` に通常敵2体と出現する。

いずれも本体HP・随伴敵数を最終ボスより抑え、戦闘画面に色・現在HP・攻略方法を表示する。中ボス勝利時の既存レリック報酬を利用する。遭遇コストはガード球45、ポケット球56、ステージ目標値は69と80。

## 検証

- Debug / x64 のゲーム本体をビルド。
- 既存Pythonテスト90件。
- `tools/test_ball_upgrade_runtime.vcxproj` のC++検証：ランHPとボール性能の独立、5種類×3段階の保存・復元と旧セーブ移行、不正セーブの拒否、強化軸の継承、衝突処理の順序、停止アンカー、貫通レリックとの組合せ、方向軽減、割合ダメージ、ステージ読み込み。
- 検証専用フォルダーで最新版を実際に起動。ランHP50、中ボス2種の出現と能力の公開、Standardの正面衝突がガード球に対して2→1ダメージになることを確認。

強化値と中ボスHPは初期調整値。長期プレイの難易度・各ビルドの勝率を比較する統計的なバランス検証は未実施。

## 主な調整場所

- `assets/data/player_status.json`：プレイヤーHP、ボールの基礎性能、2段階の強化内容。
- `assets/data/enemy_data.json`：中ボスHPと `gimmick.frontalDamageMultiplier` / `gimmick.pocketDamageRatio`。
- `assets/data/stage_01.json`：中ボスの配置と随伴敵。
- `assets/data/encounter_balance.json`：遭遇コストとステージ目標値。
