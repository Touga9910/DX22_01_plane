# Caromino 重量軸の連鎖衝突演出実装と負荷検証

作成日：2026年11月2日

## 1. 実装目的

重量軸の価値である「敵を押し込み、敵同士の衝突を連鎖させる」手触りを、既存の物理・ダメージ・スタック獲得量を変更せず視覚化した。

本実装は BallCollisionComponent で確定した衝突事実を BattleEvent、GameEvent、GamePresentation の順に渡す。GamePresentation は渡された事実を読むだけで、物理速度、ダメージ、撃破判定、敵配置、スタック計算には書き戻さない。

## 2. 実装内容

### 2.1 衝突事実イベント

CollisionImpactEvent を追加し、次の情報を一件の採用済み接触エピソードとして通知するようにした。

- 接触中心座標
- 対象敵の座標、キー、敵ID
- 衝突直前速度から求めた相対接近速度
- PlayerEnemy / EnemyEnemy / Wall の衝突種別
- 実適用ダメージ合計
- その接触で新規撃破が発生したか
- ショット中のプレイヤーボールカテゴリ

EnemyEnemy のイベント発行位置は ShotPhysicsTelemetry::RecordEnemyEnemyCollision と同じ BallPhysicsRules::Pair 採用後の経路である。このため、ダメージ0の接触も含めて CHAIN 件数と physics_chain.collision_events 件数が一致する。Wall は種別を予約し、今回は既存の壁反射演出を維持した。

### 2.2 衝撃強度

既存の固定ショット計測で確認した接近速度（約0.61～9.97）を基準に、次の3段階とした。

- 弱：2.0未満
- 中：2.0以上、6.0未満
- 強：6.0以上

入力は0～16へクランプする。負値、NaN、無限値は弱として安全側へ倒す。段階に応じてダメージ文字サイズ、リング半径、線幅、寿命、フラッシュ・カメラ揺れの要求強度を変える。

直接衝突は暖色の円と中心点、敵同士の二次衝突は寒色から暖色へ移る円と菱形で区別した。既存ダメージ文字、撃破表示、ヒット集計は維持している。

### 2.3 重量CHAIN表示

重量カテゴリのショット中に発生した EnemyEnemy の採用済み接触だけを加算する。ダメージ量や撃破の有無は加算条件に使用しない。ショット開始時に0へ戻す。

画面中央上部の一つの表示を更新する方式とし、個別テキストを大量生成しない。節目は CHAIN 3 / 6 / 10 / 15 で、色、拡大パルス、リング、許可されている場合のフラッシュ・揺れを段階的に強める。通常時も「採用された敵同士の接触回数」という意味を併記する。

### 2.4 過密対策

- 同一フレーム、同一衝突種別、距離3以内の弱・中リングは一つへ統合
- 装飾リング量 0 / 1 / 2 / 3 に対し最大同時表示数 0 / 4 / 8 / 12
- 優先度は撃破・CHAIN節目、強衝突、中衝突、弱衝突の順
- 上限到達時は低優先度を抑制し、撃破・節目は同優先度の古い装飾とも入れ替え可能
- 強衝突フラッシュは0.12秒、カメラ揺れは0.08秒、節目揺れは0.12秒のクールダウン
- カメラ揺れ要求値は最大1.5へ制限

デバッグ表示を有効にすると、受信イベント数、現在のCHAIN、同時装飾数、最大同時数、統合数、抑制数を画面左下に表示する。

## 3. 設定項目

既存の画面フラッシュ、カメラ揺れ設定を尊重し、次を追加した。

- 衝突強度演出：collision_impact_effects_enabled
- 重量CHAIN演出：heavy_chain_effects_enabled
- 装飾リング量：decorative_ring_amount（0～3、既定2）

衝突強度演出をOFFにした場合は従来のダメージリング・通常フラッシュ・通常揺れへ戻す。重量CHAIN演出は独立してOFFにでき、内部の事実カウントを物理へ返さない。

## 4. 固定ショット回帰検証

条件：seed 20260904、重量+0、power 8、方向 (-0.9916810938126976, -0.1287191057087161)、dense 8体、HP倍率1.5、画面フラッシュ・カメラ揺れ・振動は両群OFF。

過去の基準値は敵同士衝突11回。本実装後に新演出OFF 3回、ON 3回を実行した。

| 項目 | OFF 3回 | ON 3回 | 判定 |
|---|---:|---:|---|
| 敵同士衝突回数 | 11 / 11 / 11 | 11 / 11 / 11 | 一致 |
| 撃破数 | 3 / 3 / 3 | 3 / 3 / 3 | 一致 |
| 物理ステップ数 | 149 / 149 / 149 | 149 / 149 / 149 | 一致 |
| 総敵移動距離XZ | 585.56（全回） | 585.56（全回） | 一致 |
| 衝突イベント配列 | 全回同一 | 全回同一 | 一致 |
| ショット所要時間 平均 | 2468 ms | 2477 ms | +9 ms、約+0.36% |
| 物理処理時間 平均 | 243570 us | 241468 us | -2102 us、計測揺らぎ内 |

ON時の11接触は、弱5・中2・強4に分類された。CHAIN 3 / 6 / 10 はこの固定ケースで到達する。CHAIN 15 は純粋ルールテストで節目判定を確認したが、この既存固定ケースの物理結果を変更して到達させることはしていない。

フレーム時間とFPSは現在の自動ハーネスが公開していないため未計測である。上表のショット所要時間は描画を含む全体時間、physics_processing_microseconds は物理部分の参考値であり、単独でGPU負荷を表す値ではない。自動試験の全回で物理結果は同一で、演出ONによる物理処理増加は観測されなかった。

## 5. テスト結果

- BallSynergyRules、FixedTimestepRuntime、ShotPhysicsTelemetry / CollisionPresentationRules C++テスト：成功
- 確認内容：接触エピソードの再接触判定、テレメトリ件数、強度境界、負値・NaN・無限値、CHAIN段階、3/6/10/15節目、装飾上限
- 本体 Debug x64：全ソースのコンパイル成功、リンク成功
- 通常の /ZI・PDB構成は、環境内のMSPDB140.DLL / PDBサーバー版不一致で C1902 / LNK1101 が発生したため、検証時だけ /Z7 とリンカーPDBなしへ切り替えた。検証用設定は終了後にプロジェクトファイルから除去済み
- git diff --check：成功
- Python契約テスト：WindowsAppsのpython.exeが実行不能で未実行。固定ショットは同じプロトコルを使う一時Nodeハーネスで代替し、ハーネス本体は検証後に削除した
