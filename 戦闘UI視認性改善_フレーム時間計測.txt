# Caromino 戦闘UI視認性改善・VFXフレーム時間計測

作成日：2026年11月3日
対象ビルド：Debug x64

結論
----
CHAIN 10、3体撃破、ダメージ表示、撃破VFXが同時に発生する固定ショットに対し、情報の優先度と表示領域を分離した。CHAINは上部余白へ縮小配置し、MULTI BREAKはデバッグ戦闘時に右側の空き領域へ分離、ダメージ表示は撃破優先の近傍配置へ変更した。

1600×900、VSync有効、実描画ありのDebug x64でA～Dを各3回、計12回測定した。全条件で有効敵同士衝突11、撃破3、物理149ステップ、敵総移動距離585.5615844726562、重量スタック10が一致した。全演出ONのCPU描画時間は平均1.126msで、追加VFX OFF比は+0.329msだった。


A. 実装概要
============

1. ダメージ数字の配置変更
------------------------
- 表示優先度を「撃破 > 大ダメージ > 通常ダメージ」にした。
- 近傍候補を16個から24個へ増やした。
- 最初に空いた候補を採用する方式から、重なり面積と元位置からの距離を評価する方式へ変更した。
- CHAIN、MULTI BREAK、敵状態バッジの領域を配置禁止領域として評価する。
- 候補は対象周辺の限定範囲だけを使用し、全画面探索は行わない。
- 通常ダメージにも低アルファの暗色背景を追加し、緑色の盤面と白いVFXの両方に対する可読性を上げた。
- 撃破表示は先に配置し、暗い専用パネルと強い縁取りを維持する。

2. ダメージ合算の変更
--------------------
- 「3 Presentationフレーム以内」を「0.075秒以内」へ変更した。
- GamePresentation::Updateへ実経過秒を渡し、60Hz以外でも寿命と合算結果が大きく変わらないようにした。
- FloatingFeedbackへtargetKeyとcreatedTimeSecondsを保持する。
- targetKeyが同じ、0.075秒以内、距離条件内、非撃破の場合だけ合算する。
- 別の敵、対象不明、撃破表示は合算しない。
- 実ダメージイベントの件数・順序・内容は変更していない。

3. MULTI BREAKの改善
--------------------
- 背景をほぼ不透明の暗色へ変更し、橙色3px枠と左右ラインを追加。
- 本文を淡い金色にし、4方向の黒縁取りを追加。
- 3体以上は基準フォントの1.30倍、2体は1.18倍。
- 出現直後も最低72%の可視アルファを確保し、短い拡大アニメーション後に安定表示する。
- デバッグ戦闘時は画面幅70%、上端から250pxの右側領域へ配置し、CHAINと分離する。
- 通常戦闘時は中央上部へ配置し、デバッグ専用位置を通常画面へ流用しない。
- 2体でDOUBLE BREAK、3体以上でMULTI BREAK ×Nという条件は変更していない。

4. CHAINバナーの配置変更
-----------------------
- CHAIN 10以上の基準拡大率を2.55倍から2.05倍へ調整。
- デバッグ時は上端から108px、通常時は88pxを中心に配置。
- CHAIN 10以上のバナーを幅360px、高さ62pxへ縮小。
- 放射線を18本から12本へ減らし、アルファと線幅を抑えた。
- CHAIN 3 / 6 / 10 / 15、実数値、既存寿命と段階判定は維持した。
- 表示位置はImGui viewport基準で計算し、画面固定画像は使用していない。

5. VFX描画優先度
----------------
- 火花、衝撃波、ImpactBurst、高速軌跡をImGui BackgroundDrawListへ移した。
- ダメージ文字、撃破表示、CHAIN、MULTI BREAK、敵状態バッジは前面に残した。
- 撃破バーストは中心半径28→24、光条96→78、光条14→12、寿命0.42→0.36秒へ調整。
- 撃破衝撃波は終了半径12.5→10.5、太さ4.0→3.2、寿命0.46→0.38秒へ調整。
- VFX密度、同時表示上限、生成上限、優先度、ON/OFF機能は維持した。

責務分離
--------
- ApplicationはCPU時間を計測して数値をGameRuntimeへ渡すだけ。
- GameRuntimeStateが固定長サンプルと統計を所有する。新規Singletonは追加していない。
- GameMcpBridgeは読み取り用JSONへ公開するだけ。
- GamePresentationは表示配置とVFX描画順だけを担当する。
- 物理層からImGui、Renderer、計測UIを参照していない。
- GPU時間とCPU時間を混同していない。

D. フレーム時間計測
==================

計測方法
--------
- 時計：std::chrono::steady_clock。
- 総フレーム時間：描画フレーム開始間隔。待機、スケジューリング、VSyncの影響を含む。
- CPU Update：GameRuntime::Update実行時間。
- CPU Draw：GameRuntime::Draw、ImGui RenderDrawData、PlatformWindows処理のCPU実行時間。
- Present：IDXGISwapChain::Present(1, 0)のCPU待機時間。
- GPU時間：未計測。D3D11 timestamp/disjoint queryは今回追加していない。
- バッファ：512件固定長。長時間動作で増加し続けない。
- 開始：OnPlayerShotFired後。
- 終了：BallsMovingを一度確認後、同状態を抜けたフレーム。
- 初期化、アセットロード、スクリーンショット取得は測定区間外。
- game_state.jsonのframe_timingとデバッグ画面下部から確認可能。
- ポーズ設定「ショット中フレーム時間計測」でON/OFF可能。

測定環境
--------
- Debug x64、1600×900、ウィンドウ表示。
- VSync有効（Present(1, 0)）。
- 実際のDirectX11描画とImGui描画を実行。ヘッドレスではない。
- 各条件3回、計12ショット。
- 同一実行ファイル、同一seed、同一配置、60Hz要求。
- 録画・スクリーンショット取得は性能測定中に行っていない。

注意
----
Debug x64では固定物理更新が支配的で、CPU Updateが平均約42.7～43.2msとなった。そのため平均FPSは約22FPSで、Present待機は約0.3msだった。これは開発ビルドの参考値であり、製品版GPU性能の値ではない。
Release x64は固定デバッグ戦闘用の同一測定成果物を今回準備していないため未測定。

最終判定
========

派手さを残しつつ、CHAIN、MULTI BREAK、撃破、ダメージ、装飾VFXの表示領域と前後関係を分離できた。固定ショットの物理結果は全条件で一致し、全ONによるCPU描画増加はDebug x64実測で平均約0.329msだった。物理、ダメージ、敵AI、スタック、CHAIN定義は変更していない。
