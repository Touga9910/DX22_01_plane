# 生成AIを使った自動バランス調整

この機能はOpenAI Responses APIの生成AIを使用します。
ローカルのルールだけで調整値を決定するものではありません。

## 事前設定

OpenAI PlatformでAPIキーを発行し、PowerShellの現在のセッションへ設定します。
APIキーはJSONやソースコードへ保存しないでください。

```powershell
$env:OPENAI_API_KEY = "取得したAPIキー"
```

使用モデルなどは
`assets/data/balance_ai_openai.json`で変更できます。
初期モデルは`gpt-5.6-sol`です。

## 1. AI調整案を生成

ゲームの実行フォルダー（`assets`と`logs`がある場所）で実行します。

```powershell
tools\adjust_balance.cmd
```

処理内容：

1. `logs/balance/run_*.json`をローカルで集計
2. 最新の設定フィンガープリントと一致するランだけを抽出
3. 最低サンプル数などの安全条件を確認
4. 集計した特徴量をOpenAI Responses APIへ送信
5. 生成AIがJSON Schema準拠の調整案を返す
6. ローカルで対象・方向・現在値・変更幅を再検証
7. `logs/balance/balance_adjustment_plan.json`へ保存

元のステータスはまだ変更されません。

通常は最新設定のコホートが自動選択されます。過去の特定設定を
再解析する場合は、フィンガープリントまたは一意な接頭辞を指定します。

```powershell
tools\adjust_balance.cmd --configuration-fingerprint 3d6c7f36
```

指定した接頭辞が複数の設定に一致する場合は、誤調整を防ぐため処理を
停止します。選択結果は調整計画の `source.run_selection` に記録されます。

## 2. 確認後に適用

```powershell
tools\adjust_balance.cmd --apply
```

適用前の`enemy_data.json`は
`logs/balance/backups`へ日時付きで保存されます。

## 安全条件

- ステージごとに30件以上の完了ログが必要
- ローカル評価を通過した敵だけをAIへ提示
- 一度の調整で使うのは単一の設定フィンガープリントのランだけ
- AIが変更できるのは敵の`maxHp`と`attack`だけ
- 1回の変更量は最大±1
- 難易度の変更方向とログ評価が一致しない案は拒否
- 同じ敵を一度に複数変更する案は拒否
- AIが参照したステージIDも検証
- `--apply`なしではステータスを変更しない
- 適用前に必ずバックアップを作成
- APIキーがない、通信失敗、形式不正の場合は何も変更しない

調整基準は`assets/data/balance_targets.json`、
安全制限は`assets/data/balance_adjustment_policy.json`、
AI設定は`assets/data/balance_ai_openai.json`で管理します。

## 収集から調整までの無人実行

ゲームとMCPサーバーを起動した状態で次を実行します。

```powershell
tools\auto_balance.cmd
```

`tools/auto_balance_loop.py` は次の状態機械を連続実行します。

1. 現在の設定ファイルからフィンガープリントを計算
2. 同じフィンガープリント、プレイヤーレベル、ビルド方針のランだけを選択
3. 固定シードと `dda_off` を使い、完走ランが `balance_targets.json` の最低件数へ達するまで不足分を収集
4. シード種類数、完走率、単一シードへの偏り、実行時間の外れ値率を検証
5. ローカルのサンプル品質・ボス到達ゲート・調整幅検証を通過した場合だけAIへ送信
6. 主プロファイルと回帰確認プロファイルの基準ランをその反復内で新規収集し、適用前の同一シード基準値を保存
7. 設定一式を世代バックアップしてからAI案を適用
8. 新しいフィンガープリントで同じシードを再実行し、主プロファイルの改善と他プロファイルの非退行を確認
9. 検証失敗時は適用前バックアップへ戻して停止、合格時は新コホートを0件から収集
10. 目標内、または安全停止条件へ達するまで繰り返し

設定は `assets/data/auto_balance_loop.json`、実行状態と停止理由は
`logs/balance/auto_balance/state.json` に保存されます。途中で異常終了しても、
適用済み履歴とコホート件数は消えません。設定適用の途中で終了した場合は、
次回起動時に `pending_apply` を検出し、適用前の設定一式へ自動復元して停止します。

`logs/balance/auto_balance/loop.lock` はOSのファイルロックとして使用されます。
同じプロジェクトで2つ目の自動調整を起動しても、状態や設定を変更せず終了します。
プロセス終了時にはOSがロックを解放するため、残ったファイル自体を削除する必要は
ありません。

設定一式のバックアップは `logs/balance/backups/auto_balance` に保存されます。
新しいコホートでスコア改善が既定回数確認できなかった場合、直前の設定へ自動復元
して停止します。

### 同一シードと複数プロファイル検証

`paired_validation` は中級者・standardの既定5シードを調整前後で
再利用します。ゲームのラン乱数に加え、MCPのショット誤差も
シードから再現されます。既定ではバランススコアが0.5以上
改善し、全シードが終端結果へ達する必要があります。

`holdout_validation` は調整用とは重複しない未使用5シードを使い、
中級者・standardの改善が未知条件でも維持されるか確認します。

`regression_validation` は初心者・standard、上級者・standardに加え、
中級者のheavy、pierce、bounce、anchorを各2シードで比較し、
スコア退行を5.0までに制限します。いずれかのケースが
不合格なら、設定を自動ロールバックして停止します。プロファイル、
ビルド方針、シード数、許容退行量は
`assets/data/auto_balance_loop.json` で変更できます。

### 時間・ラン数・AI利用量の上限

`budgets` で実行開始からの経過時間、完了ラン数、AI呼び出し回数、
総トークン数、推定料金を制限します。既定上限は24時間、400ラン、
AI 10回、10万トークン、5.00 USDです。収集コマンドは2時間、
AI生成コマンドは5分でタイムアウトします。超過時は設定を変更せず
`state.json` へ利用量と停止理由を保存します。

推定料金は `pricing_usd_per_million_tokens` の入力、キャッシュ入力、
出力単価をResponses APIの利用量に掛けて算出します。モデルや料金を
変更した場合は、この単価も同時に更新してください。

実際の収集やAPI呼び出しを行わず、現在の準備状態だけ確認できます。

```powershell
tools\auto_balance.cmd --dry-run
```

### 自動停止条件

- 同じ敵・項目で直近の調整と逆方向の案が出た
- 過去と同じ `enemy_data.json` へ戻る案が出た
- 同じ敵・項目を同方向へ既定回数以上変更しようとした
- 新しいコホートのバランススコアが連続して改善しない
- サンプル品質を満たせないまま同一フィンガープリントの収集上限へ達した
- 信頼区間が判定境界と重なったため追加収集し、最大試行数でも確定できなかった
- AI評価中に人手や別ツールによる設定変更を検出した
- 同一シード、ホールドアウト、または複数プロファイル・ビルドの回帰確認に失敗した
- 時間、ラン数、AI回数、トークン、または推定料金の上限に達した
- AIが変更を見送った、データ品質に問題がある、または最大反復回数へ達した

逆方向案は適用前に停止するため、例えば `attack +1` の次に
`attack -1` を適用して元へ戻す往復は発生しません。
停止時はコンソールへ `auto_balance_stopped` または
`auto_balance_completed` のJSONイベントを出力し、同じ理由と詳細を
`state.json` にも保存します。
