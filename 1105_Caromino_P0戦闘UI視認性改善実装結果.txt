# Caromino P0 戦闘UI・視認性改善 実装結果

作成日: 2026-11-05  
対象: SE以外の戦闘UI・Presentation  
前提資料: `1104_Caromino審査会改善対応調査計画.txt`

## 1. 実装した機能

### 敵HP表示

- 生存中の通常敵・強敵・タンクを含む全敵に、現在HP/最大HPのバーを表示する。
- ダメージ直後は現在値を即時反映し、遅れて縮む残量チップを約0.28秒表示する。
- HP、行動、状態、Anchorスタックを1つの表示ブロックとして配置する。
- 画面端補正と9候補のスクリーン座標配置を使い、密集時は既配置ブロックとの重なりが最小の位置を選ぶ。
- 10体Dense配置で、全敵のHPと行動が盤面上で追跡できることを確認した。

### 敵行動予告

- 既存の「待・攻・溜・強」バッジを継続利用した。
- 確定済みの現在行動だけを表示し、未確定の次行動は確定事項として表示しない。
- Attack/StrongAttackはプレイヤー対象を `P`、確定済みの予想ダメージを `-N` で表示する。
- ChargeStartは「準備」として通常攻撃と区別する。
- ツールチップに対象、予想ダメージ、攻撃前シールドを表示する。
- 予想値は既存 `EnemyAttackComponent::CalculateDamage` の確定データを参照し、敵AI・攻撃予算・ダメージルールは変更していない。

### 4軸スタック増減表示

- 重量・貫通・反射・Anchorについて、変化前、変化後、差分、理由、能力ID、FINISHERを値イベントで通知する。
- 同一フレームかつ同一軸・同一対象の変化は1件へ集約する。
- プレイヤー側はHUD近傍、敵側Anchorは対象敵近傍へ表示する。
- 獲得と消費を色・符号で区別し、FINISHERは専用文言を付ける。
- デバッグ戦闘の比較検証中も新規Presentationイベントを表示できるようにした。自動プレイの戦闘ルールは変更していない。

### ショット終了サマリー

- 物理停止とEndOfShot処理確定後に `ShotResolvedEvent` を1回発行する。
- 約2.15秒、総ダメージ、命中数、撃破数、Charge妨害数、軸の獲得/消費、FINISHERを優先度付きで表示する。
- 情報がないショットは `NO HIT` を表示する。
- 既存の瞬間的なダメージ表示とは役割を分け、右側の固定領域に結果だけを集約する。
- デバッグ戦闘で `SHOT RESULT / DMG / HIT / NO HIT` の実表示を確認した。

### 大量衝突時の整理

- 非撃破ダメージ数字の同時表示上限を8件にした。
- 同一対象の近接時間内の表示集約時間を0.075秒から0.16秒へ拡張した。
- HP/行動ブロック、ショットサマリー、連鎖表示を保護領域として扱い、浮動表示が重要情報へ被りにくくした。
- 既存 `CollisionVfxSystem` を継続利用し、新しいManager/Singletonは追加していない。

## 3. 変更前後の挙動

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 敵HP | 敵種・状況によって即時比較しづらい | 全生存敵に現在/最大HPと遅延減少表示 |
| 行動予告 | 「待・攻・溜・強」が中心 | 既存バッジに確定対象と確定予想ダメージを追加 |
| 軸リソース | 最終値は見えるが増減理由が追いづらい | 前後値・差分・理由・能力・FINISHERをイベント表示 |
| ショット成果 | 瞬間表示を記憶する必要がある | 終了時に重要結果だけを約2.15秒集約表示 |
| 大量衝突 | 数字/VFXが重要情報と競合しやすい | 数字上限、時間集約、保護領域で競合を軽減 |

## 4. EventとPresentationの責務分担

```text
Physics / Rules
  └─ 既存計算を実行（変更なし）
       └─ GameProgression
            ├─ 確定値をGameEventへ変換
            └─ 1ショット分の値を集計
                 └─ GamePresentation
                      ├─ 表示時間・色・配置・集約
                      ├─ HP遅延バー
                      └─ ショット結果パネル
```

- Eventは描画型、ImGui型、Renderer型を持たず、値データだけを渡す。
- Physics/RulesはImGui/Rendererを参照しない。
- Gameクラスにはイベントの橋渡しと既存確定点での通知だけを置き、表示レイアウトは `GamePresentation` に限定した。
- 敵行動、物理、ダメージ、スタック計算そのものは変更していない。

## 6. 性能比較

Release x64、通常表示の単一ショット計測。厳密な同一フレーム列A/Bではないため参考値とする。

| 指標 | 既存基準 | UI追加後 | 判定 |
|---|---:|---:|---|
| 平均フレーム時間 | 約16.67ms | 16.68ms | 約60FPSを維持 |
| p95 | 16.667ms | 16.68ms | 目標範囲 |
| p99 | 16.687ms | 17.19ms | 一時的増加、許容範囲 |
| 最大 | 16.758ms | 17.19ms | 一時的増加、許容範囲 |
| Draw平均 | 0.262ms | 0.16ms | 悪化なし |

デバッグ調整UIを開いた状態ではDraw平均0.59msだったが、平均フレーム時間は16.68msで60FPS帯を維持した。

## 8. 残された課題

1. Debug PDBツールチェーンの `MSPDB140.DLL` をVisual Studio/MSVC 14.38へ揃え、標準設定のDebugリンクを再確認する。
2. 現行UIでCHAIN 10以上を固定入力として再現できるプリセットを保存し、同条件の性能値とスクリーンショットを取得する。
3. GameMCPは検証中にHTTP 429となったため、レート制限解消後に同じ固定条件をMCPから再実行し、画面確認とログを1つの手順へ統合する。
4. 10体を超える将来の敵数や極端な画面比率では、HPブロックの縮小・重要敵優先表示を追加検討する。
